# 서비스 소개

일반적인 영화 소개에서 벗어나, 나에게 맞는 나만의 영화 추천을 할 수 없을까? 라는 생각에서 출발했습니다.<br />
커스텀된 영화 추천을 위해 사용자가 느끼는 감정에 주목했고, 영향을 받는 날씨나, 시간 등의 카테고리를 추가했습니다. <br />

# 설명

<h3>영화 추천 받기</h3> <br />
<img width="426" height="240" alt="영화 추천" src="https://github.com/user-attachments/assets/3db6a17a-5939-4eed-8a0b-10c7ca01f279" /> <br />


추천 조건 선택 → 날씨·선택값을 Gemini API에 전달 → 영화 제목 10개 생성 → TMDB에서 포스터 조회 <br />
→ 첫 4개 이미지 로딩 완료 시 결과 표시 → 나머지 영화 추가 <br />

- 추천 페이지 진입 시 사용자의 위치를 이용해 날씨 정보를 가져옵니다.
- 위치 정보 조회가 실패하거나 일정 시간 안에 끝나지 않으면 기본 날씨 데이터를 사용합니다. 
- 사용자는 날씨, 감정, 장르, 시청 시간대를 선택할 수 있으며, 추천 버튼을 누르면 네 항목이 모두 선택되었는지 검사합니다. 
- 이 화면의 선택값은 현재 컴포넌트의 React state로 관리합니다.
- 검증을 통과하면 브라우저가 날씨 정보, 사용자 선택값, 이전에 추천받은 영화 제목을 POST /api/geminis로 보냅니다. 
- Next.js API는 GetGeminiMovieRecommendationUseCase를 호출합니다. 
- UseCase는 전달받은 조건과 이전 영화 목록으로 프롬프트를 만들고 Gemini에 영화 10편의 한국어·영어 제목을 요청합니다. 
- Gemini 응답에서 제목 목록을 추출해 브라우저로 반환합니다.
- 브라우저는 우선 제목 6개를 POST /api/movies/search/batch로 보냅니다. 
- 배치 API는 각 제목으로 TMDB 검색을 병렬 수행하고, 포스터가 있는 영화의 movieId, title, posterUrl을 반환합니다. 
- 유효한 결과가 4개 이상이면 추천 포스터를 화면에 표시하면서 나머지 제목도 백그라운드에서 조회해 목록에 추가합니다. 
- 화면에 처음 보이는 포스터 4장의 이미지 로딩이 실제로 완료되면 로딩 화면을 닫고 완료 메시지를 표시합니다. 
- 첫 조회에서 포스터를 4개 확보하지 못하면 남은 제목을 추가 조회하고, 필요할 경우 재추천을 시도합니다.

<h3>영화 검색</h3> <br />

<img width="426" height="240" alt="영화 검색 흐름" src="https://github.com/user-attachments/assets/f47a9c71-fe67-4a43-8e47-19ed8a0b06d4" /> <br />

검색 화면 진입 → TMDB 주간 인기 영화 중 8개 표시 → 검색어 제출 → 영화·TV·인물 통합 검색 → 유형별 결과 표시 → 영화 상세 또는 인물 출연작 확인 <br />

- 검색 화면에 처음 들어와 검색어가 없으면 브라우저가 GET /api/search/trending?page=1을 호출합니다. 
- 서버는 TMDB의 주간 인기 영화(/trending/movie/week)를 조회합니다. 
- 브라우저는 포스터가 있는 결과만 남기고, 그중 무작위 8개를 선택해 초기 화면에 표시합니다.
- 사용자가 제목, 감독, 배우 등의 검색어를 입력하고 Enter 또는 검색 버튼을 누르면 검색어가 URL의 keyword 쿼리 파라미터에 반영됩니다. 
- 검색 결과 컴포넌트는 GET /api/movies/search?query=...를 호출하고, Next.js API는 TMDB의 통합 검색(/search/multi) 결과를 반환합니다. 
- 브라우저는 이미지가 없는 항목을 제외한 뒤, 사용자가 선택한 type 값에 따라 전체·영화·TV·인물 결과를 필터링해 표시합니다. 유형 변경도 URL 쿼리에 반영됩니다.
- 영화 결과를 선택하면 영화 ID를 확인해 상세 모달을 엽니다. 인물 결과를 선택하면 /search/artist?name=...로 이동합니다. 
- 해당 화면은 인물 검색 결과에서 ID를 찾고 출연작 API를 호출한 뒤, 포스터가 있는 영화 출연작을 최신순으로 최대 20개 표시합니다. 
- 검색 및 초기 인기 영화 표시는 DB 저장 없이 TMDB 데이터를 조회하는 기능입니다.


<h3>댓글 등록</h3> <br />
<img width="426" height="240" alt="댓글등록" src="https://github.com/user-attachments/assets/d312089b-874a-48d2-b27c-7fef8f1c0188" /> <br />


영화 상세 화면 진입 → 기존 한줄평 조회 → 내용 입력·등록 → 쿠키의 토큰으로 사용자 확인 <br />
→ DB reviews 저장 → 목록 재조회 <br/>

- 영화 상세 화면은 영화 ID를 기준으로 GET /api/reviews?movieId=...를 호출해 기존 한줄평을 가져옵니다. 
- 사용자가 내용을 입력하고 등록하면 브라우저가 movieId와 content를 POST /api/reviews로 전달합니다. 공백만 입력한 경우에는 요청하지 않습니다.
- Next.js API는 요청 쿠키의 액세스 토큰을 검증해 사용자 ID를 추출합니다. 인증되지 않았다면 등록을 거절합니다. 
- 인증에 성공하면 CreateReviewUseCase가 사용자 ID, 영화 ID, 내용을 담은 리뷰를 생성하고, ReviewRepositoryImpl이 DB reviews 테이블에 user_id, movie_id, content를 저장합니다.
- 저장 요청이 성공하면 입력창을 비우고 같은 영화의 한줄평 목록을 다시 조회합니다. 
- 조회 결과는 작성 시각 내림차순으로 가져오므로 새 한줄평과 갱신된 개수가 화면에 반영됩니다. 
- 인증 오류에 대한 로그인 안내와 토큰 재발급 시도는 공통 Axios 인터셉터에서 처리합니다.


<h3>회원가입 및 로그인</h3> <br />
<img width="426" height="240" alt="회원가입 및 로그인" src="https://github.com/user-attachments/assets/f32974a5-fabe-4d8d-8a89-3e5338d0b903" /> <br />

회원 정보 입력 → 클라이언트·서버 검증 → 비밀번호 해시 → DB users 저장 → 회원가입 완료 <br />
로그인 → 비밀번호 비교 → JWT 쿠키 발급 → 사용자 상태 저장 <br />

- 회원가입 화면에서 이름, 이메일, 비밀번호, 비밀번호 확인, 닉네임을 입력합니다. 
- 브라우저는 입력 중 형식과 비밀번호 일치 여부를 확인하고, 제출 시 POST /api/auth/signup을 호출합니다. 
- 서버의 CreateSignupUseCase는 이름·이메일·비밀번호·닉네임 형식을 다시 검사하고, DB users 테이블에서 이메일과 닉네임 중복 여부를 확인합니다. 
- 이후 비밀번호를 해시해 users 테이블에 사용자 정보를 저장합니다.
- 가입에 성공하면 회원가입 완료 화면이 나타납니다.
- 로그인 시 브라우저는 이메일과 비밀번호를 POST /api/auth/signin으로 보냅니다. 
- 서버는 DB users 테이블에서 이메일로 사용자를 조회하고, 입력한 비밀번호를 저장된 해시와 비교합니다. 
- 인증에 성공하면 사용자 ID를 담은 액세스 토큰과 리프레시 토큰을 발급해 HttpOnly 쿠키에 설정합니다. 
- 비밀번호를 제외한 사용자 정보는 브라우저로 반환되며, 화면에서는 이를 상태관리에 저장한 뒤 메인 페이지로 이동합니다. 
- 인증이 필요한 후속 API는 쿠키의 토큰으로 사용자를 확인하고, 액세스 토큰이 만료되면 공통 Axios 인터셉터가 리프레시 토큰으로 재발급을 시도합니다.

<h3>마이페이지</h3> <br />
<img width="426" height="240" alt="마이페이지" src="https://github.com/user-attachments/assets/ce91aeef-e2d6-423c-96b1-0997155818d1" /> <br />

로그인 및 토큰 쿠키 발급 → 마이페이지 접근 확인 → 캘린더·한줄평·볼래요 데이터 조회 <br />
→ 필요한 영화 제목·포스터를 TMDB에서 보완 → 마이페이지의 세 영역에 표시 <br />

- 로그인에 성공하면 서버가 액세스 토큰과 리프레시 토큰을 HttpOnly 쿠키로 설정하고, 브라우저는 비밀번호를 제외한 사용자 정보를 저장합니다.(Zustand)
- 사용자가 헤더의 프로필 아이콘을 눌러 /mypage로 이동하면 AuthPageGuard가 저장된 사용자 상태를 확인합니다. 사용자 정보가 없으면 로그인 화면으로 이동합니다.
- 마이페이지 상단의 이름·닉네임·이메일·프로필 이미지는 상태관리(Zustand)에 저장된 사용자 정보로 표시합니다. 

1. 영화가 머문 날: 캘린더 <br />
실제로 영화를 본 날 뿐만 아니라, 보고 싶은 날에 미리 영화를 저장해두는 일정같은 기능으로 생각하시면 됩니다. <br />

영화 상세에서 날짜 선택 → DB calendar 저장 → 마이페이지에서 연·월 조회 → TMDB 영화 정보 결합 → 날짜별 포스터 표시 <br />

- 영화 상세 화면에서 사용자가 영화를 기록할 날짜를 선택하면, 브라우저가 영화 ID와 선택 날짜를 POST /api/saves로 전달합니다. 
- 서버는 쿠키의 토큰에서 사용자 ID를 추출하고 날짜 형식을 검사합니다. 
- 같은 날짜에 다른 영화가 있는지, 같은 영화가 다른 날짜에 저장되어 있는지 확인한 뒤 DB calendar 테이블에 user_id, movie_id, saved_at을 저장합니다. (현재는 하루에 하나의 영화만 저장 가능)
- 마이페이지에 들어오면 캘린더는 현재 연도와 월을 GET /api/saves?year=...&month=...로 보냅니다. 
- 서버는 calendar 테이블에서 해당 사용자와 해당 월의 기록을 조회합니다. 
- 저장된 영화 ID마다 TMDB의 상세 정보를 병렬로 가져와 제목과 포스터 URL을 붙인 다음 화면에 반환합니다. 
- 화면은 savedAt 날짜에 맞는 칸에 영화 포스터를 표시합니다. 이전·다음 달 버튼을 누르면 바뀐 연·월로 다시 조회합니다.
- 현재 마이페이지 캘린더 코드는 날짜 칸마다 조회 결과에서 첫 번째로 일치하는 영화 한 편을 표시합니다. 

2. 한줄평 (내가 쓴 댓글 모음)  <br />
영화 상세에서 한줄평 등록 → DB reviews 저장 → 마이페이지에서 내 한줄평 조회 → TMDB 영화 제목 결합 → 최근 3개·전체 목록 표시  <br />

- 영화 상세 화면에서 작성한 한줄평은 POST /api/reviews를 거쳐 DB reviews 테이블에 사용자 ID, 영화 ID, 내용으로 저장됩니다.
- 마이페이지의 한줄평 영역은 먼저 GET /api/saves/user-auth로 쿠키의 토큰을 확인하고 사용자 ID를 받습니다. 이어서 GET /api/reviews?userId=...로 그 사용자의 한줄평을 조회합니다.
- 서버의 리뷰 Repository는 reviews 테이블을 user_id로 필터링하고 작성 시각 최신순으로 반환합니다.
- 화면에는 전체 작성 개수와 최근 한줄평 3개를 보여줍니다.
- 각 기록의 영화 ID로 GET /api/movies?movieId=...를 호출해 영화 제목을 가져와, 영화 제목·작성 날짜·한줄평 내용을 함께 표시합니다.
- 더보기를 누르면 모달에서 전체 한줄평을 조회해 보여줍니다.
- 마이페이지의 이 영역은 작성 내역을 보여주는 화면이며, 새 한줄평 등록은 영화 상세 화면에서 진행합니다.

3. 볼래요 (찜하기 기능) <br />

영화 상세보기에서 볼래요 저장 → DB saved_watch 저장 → 마이페이지에서 저장 목록 조회 → TMDB 포스터·제목 결합 → 미리보기·더보기 표시 <br />

- 사용자가 영화 상세 화면에서 볼래요에 영화를 추가하면 서버가 인증된 사용자 ID와 영화 ID를 DB saved_watch 테이블에 저장합니다.
- 마이페이지에서는 GET /api/mypage/saved-watches?maxLength=6을 호출합니다. 
- 서버는 토큰에서 사용자 ID를 확인한 뒤 saved_watch 테이블에서 전체 저장 개수와 화면에 표시할 최대 6개 항목을 조회합니다. 
- 브라우저는 반환된 영화 ID 각각으로 /api/movies/{movieId}를 호출해 TMDB 영화 제목과 포스터를 가져오고, 3열 포스터 목록으로 표시합니다. 
- 포스터 정보 조회에 실패하면 기본 이미지를 사용합니다.
- 더보기를 누르면 모달이 열리고 목록을 다시 조회해 최대 20개 포스터를 보여줍니다. 
- 제목 및 포스터는 TMDB에서 가져오며, 사용자가 어떤 영화를 저장했는지에 대한 기록만 DB saved_watch에 저장합니다.



# 역할

정훈 <br >
영화 추천 시스템(feature/recommender)
- 기상청 API 파싱
- 추천페이지 내 사용자의 감정, 장르, 시간정보 저장 (Zustand)
- 프롬프트 및 Gemini AI 연동
- 추천 영화 렌더링
영화 저장 시스템<br >(feature/save)
- 사용자, 영화id, 날짜 저장 및 영화 포스터 받아오기<br >

소연<br />
회원 등록 시스템(feature/signin)
- 회원정보를 db에 저장
feature/user
- signin에서 파생함. user와 관련된 정보<br >

지나<br />
영화 조회 시스템(feature/search)
- tmdb에서 제목, 감독 등을 이용해 영화 리스트 반환<br >
영화 리뷰등록 시스템(feature/review)
